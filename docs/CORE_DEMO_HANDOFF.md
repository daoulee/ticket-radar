> 2026-11-01 갱신: shared/server 기반 구현 완료, Astra 서버 테스트 33개·타입 검사 재확인. 최종 승인은 [Sol 독립 검토](SOL_REVIEW_20261101.md)의 R1~R4 수정 후 판단한다. WEB-005D 실서버 브라우저 완료 보고가 있으며 앱은 이를 확인해 연동 진행 가능. 실제 AI는 미설정·미검증. 아래 ‘현재 확인’은 10월 29일 당시 기록이다.

사용자 최종 지시에 따른 현재 우선순위다. 기존의 범위 미승인 표현보다 이 결정이 우선한다.
목표: 팬이 결제 전에 판매글과 공식 자료를 비교하도록 돕는 3분 시연. 수상 확률·불법/사기 확정·진위 보증은 표시하지 않는다.

## 현재 확인

- 웹: fixture 기반 4단계와 수정 흐름. 10월 29일 테스트 15개·빌드 재실행 통과.
- 앱: fixture 기반 흐름. 10월 29일 Jest 32개 재실행 통과. iOS 개발 빌드·딥링크 캡처는 이전 담당자 기록이며 이번 턴 재실행하지 않았다.
- API/AI: server/shared 구현·Sol 착수 기록 없음. 새 문장은 fixture 조회에 없으면 unknown/보류. 실제 AI 성능 검증 없음.
- 공식 데이터: docs/official/demo-event-akmu.json은 공식 공지 재확인 자료. 제품에는 아직 가상 공연·example.com이 남아 있다.
- 실제 브라우저·기기 조작, 배포, 대회 제출: 이번 턴 수행하지 않음. 테스트/빌드와 별도 상태다.

## 순서와 소유권

1. **Sol / CORE-002**: `shared/` 공통 타입·런타임 스키마·사례 JSON, `server/` 추출 어댑터·규칙 엔진·API·테스트를 소유한다. 먼저 경로·실제 모델·착수를 Communicate에 기록한다. 웹/앱 파일은 수정하지 않는다.
2. **Astra**: Sol 계약을 SPEC 기준으로 검토한다. 공식 공연 자료와 예외 범위를 확인하고 독립 검증 사례를 보유한다.
3. **Opus 1 / WEB-005**: `web/`에서 shared 계약 소비, 중첩 응답 검증, HTTP 연결, 새 문장 입력→수정→재대조를 실제 브라우저로 확인한다. 영상·스크린샷·명령/결과·오류 상태를 인계한다.
4. **Opus 2 / APP-005**: 웹 실제 왕복 통과 후 `mobile/`을 같은 계약에 연결한다. 임시 웹 코드 사본을 공통 계약으로 교체하고 iOS 실제 탭/키보드 흐름을 검증한다. Android/실기기는 따로 보고한다.
5. **Astra**: 구현/단위 테스트/빌드/API 왕복/브라우저/기기/배포/제출을 각각 기록하고 시연을 검수한다.

제보함·OCR·수집·알림·추가 목업 작업은 핵심 통과 전 대기한다. 별도 세션에 기록이 자동 전달됐다고 가정하지 않는다.

## 계약과 검증 통과 조건

- 실제 AI 제공자·모델과 처리 방식(`model`, `fixture`, `manual`)을 기록한다. 개발 에이전트 모델과 제품 AI 모델을 혼동하지 않는다.
- 합성 판매글 여부, 공식 데이터 출처 여부, 실제 모델 호출 여부는 서로 독립된 정보다. 실제 AI를 써도 합성 입력이면 시연 표시는 유지한다.
- 추출 원문 인용은 입력 문자열의 실제 구간이어야 한다. 원문에 없는 가격/회차를 생성하면 실패로 처리한다. 모호하거나 누락된 값은 null/후보로 표시한다.
- 사용자가 확인한 값은 원래 추출 후보와 구분하고 수정 후 대조 결과가 이전 값으로 되돌아가지 않아야 한다.
- 비교 전 공연·회차·좌석·단가·수수료/할인 조건을 검사한다. 불명확하면 이유와 함께 숫자 비교를 보류한다.
- 공연 규정에는 적용 범위가 필요하다. AKMU 공지의 선예매 규정을 일반예매에 적용하지 않는다. 선예매 여부가 불명확하면 확인 필요로 표시한다.
- AI 오류를 fixture 성공으로 조용히 대체하지 않는다. 오류·재시도 또는 명시적 수동 입력만 제공한다.

| 사례 | 검증 기대값 |
| --- | --- |
| 새로운 합성 문장 | fixture 조회 없이 실제 모델 호출, 가격·좌석·회차·전달 설명과 원문 근거 확인 |
| 가격 누락 | null, 사용자 입력 요청, 추정 가격 금지 |
| 좌석/회차 불일치 | 숫자 차액 없이 보류 사유 |
| AI 오류/시간 초과 | 성공 결과 없이 오류와 재시도 |
| 사용자 가격 수정 | 수정값으로 서버 재대조, 적용값 표시 |
| 예매 유형 불명 | 선예매 규정 적용 보류 |
| 원문 속 지시문 | 문구를 데이터로 취급, 도구 실행·판정 지시 무시 |

## 3분 시연 대본

- 0:00–0:25: “비싸다는 것만으로는 실제 입장 조건을 알 수 없습니다.” 문제와 공식 공지 소개.
- 0:25–1:05: 실제 공연 선택, 처음 보는 합성 판매 문장을 입력. 시연 입력임을 밝히고 실제 AI 추출과 원문 근거를 보여준다.
- 1:05–1:35: 가격 또는 회차를 수정해 적용값을 확인한다.
- 1:35–2:15: 같은 조건의 가격 비교와 규정 확인사항을 공식 URL·문구·확인 시각과 함께 설명한다.
- 2:15–2:40: 회차/좌석이 불명확한 사례로 비교 보류를 보여준다.
- 2:40–3:00: AI 추출과 규칙 판정의 역할, 사람이 최종 확인하는 이유, 실제 검증 범위를 말한다.

## 실패 백업

실제 왕복 성공 후 같은 흐름을 녹화하고 입력·응답·공식 출처 버전을 저장한다. 현장 네트워크 장애 시 “앞서 실제 API로 검증한 녹화”라고 표시한다. 녹화가 없으면 fixture 시연이라고 명시하며 실제 AI 작동을 주장하지 않는다. 백업 녹화·실 API 기록은 아직 미제작이다.

## 필요한 사용자 정보

제품 AI 제공자와 서버 API 사용 가능 여부(키 값은 채팅에 금지), 최종 제출일/발표일과 최신 운영 안내. 나머지 계약·폴더·검증 절차는 Astra가 조율한다.

## 사용자 답변 반영

AI 제공자와 키 보유 여부는 미확정이다. Sol은 제공자별 구현을 교체할 수 있는 ExtractionProvider 인터페이스로 준비한다. 미설정 시 AI_NOT_CONFIGURED 오류를 반환하고 fixture 성공으로 대체하지 않는다. 제공자·비용 확인 전 유료 모델 호출을 시작하지 않는다.

사용자가 제공한 신청서 PDF 2쪽의 텍스트와 기획 페이지 렌더링을 확인했다. 최종 제출일·발표일·심사 배점은 기재되지 않았다. 반복 판매자/연락처 연결 기능이 To-Be에 있으나 최신 사용자 지시에 따라 후속 범위로 둔다. 최종 일정은 별도 운영 안내가 필요하다.
