## Sol 수정 요청

### R1 · P1 · 복합 한글 금액을 잘못 검증
- 위치: server/src/extraction.ts numericEvidence(12~15행).
- 재현: 원문 `VIP 한 장 17만6천원입니다.`, 인용 `17만6천원`. 가격 170000과 6000은 검증 통과, 올바른 176000은 거부된다.
- 영향: 모델이 잘못 추출한 값을 원문 근거가 있다고 승인하고 올바른 응답은 오류 처리한다. 사용자 확인 단계가 있지만 근거 검증 결함은 남는다.
- 완료 기준: 복합 금액 전체를 해석하거나 지원하지 못하면 보수적으로 거부. 부분 토큰 금액은 통과시키지 말 것. `17만6천원`, `17만 6천 원`, 단일 `17만원`, 두 별도 금액을 포함한 문장 회귀 테스트. 실제 AI 정확도와 구분.

### R2 · P1 · 작성한 설명이 공식 원문 필드에 들어감
- 위치: server/src/catalog.ts priceTiers.sourceText → rules.ts officialExcerpt.
- 현재 `공식 공지 기본가: VIP 176000원. 수수료·할인 제외 기본가 비교.`는 코드에서 합성한 문장이다. 그런데 응답의 officialExcerpt로 제공된다.
- 영향: 서비스가 작성한 비교 기준을 공식 공지의 직접 인용처럼 표시할 수 있다.
- 완료 기준: 실제 공식 가격 문구를 확인해 원문 인용으로 보존하고, 정규화한 가격·비교 범위 설명은 별도 필드/설명으로 분리. 공식 자료 편집은 Astra 소유 docs/official 변경 요청으로 인계. 원문 확보 전 생성 문장을 직접 인용으로 발표하지 말 것. 이번 검토는 공식 페이지 최신 재조사가 아님.

### R3 · P2 · 회차별 계산과 인용 근거 불일치
- 위치: server/src/rules.ts 26행. comparePrice는 회차를 확인하지만 createFindings는 좌석 등급만 find한다.
- 재현: 같은 VIP 1회차 100000원, 2회차 200000원의 합성 기준. 2회차 비교 계산은 200000원을 사용하면서 officialExcerpt는 1회차 100000원 문구를 반환한다.
- 완료 기준: 계산에 사용한 동일 priceTier의 문구·URL·확인일을 일관되게 전달. 회차별 동일 좌석 등급 회귀 테스트. 현재 AKMU 단일 공통 가격에서는 드러나지 않는 결함.

### R4 · P2 · 원문 인용 없는 판단을 공통 스키마가 허용
- 위치: shared/index.ts FindingSchema 85~94행.
- 재현: 정상 수동 응답에서 모든 finding.listingQuote를 null로 바꿔도 CheckResponseSchema 통과.
- 완료 기준: SPEC의 conflict/matched/needs_check 원문 근거 요구를 런타임 스키마에 반영하고 거부 테스트 추가. 수동 입력의 전체 원문 인용은 현재 유지한다. 확인값과 원문이 다를 수 있음을 명시하고, UI는 접어 보기 가능. nullable 예외가 필요하면 원문 근거와 사용자 입력 근거를 구분하는 계약 제안을 먼저 제출할 것.

## 남은 기능·검증 경계

- 전달 방식은 추출 필드에 있으나 현재 규칙은 선예매 본인 여부 중심이다. 전달/수령 방식 자체에 관한 공식 규정 대조까지 완료됐다고 발표하지 않는다. 실제 공식 문구 확보 후 적용 조건·테스트를 정해야 한다.
- 실제 AI 제공자/모델 미정. Ollama 어댑터와 모의 제공자 테스트는 실제 AI 추출 증거가 아니다.
- WEB-005D가 이번 검토 중 등록됨: 웹 담당은 실서버 브라우저 왕복·35개 단위 테스트·12개 브라우저 테스트를 보고했다. Astra가 이번 턴 독립 재실행한 결과는 아니다. 앱은 해당 인계 확인 후 실서버 연동 진행 가능.
- 회차 label은 startsAt을 화면에서 현지화하는 현재 방식 허용. 서버 label 변경은 필수 수정 아님.
- 공식 확인 시각은 아직 날짜 단위. 서버 처리 시각을 공식 확인 시각으로 대체하지 말 것.
- 배포·실기기·대회 제출 미검증.
