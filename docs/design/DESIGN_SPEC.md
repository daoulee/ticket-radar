# 티켓레이더 UI/UX 필수 지침 v1

상태: 2026-11-02 사용자 리디자인 요청에 따라 Astra가 확정한 구현 기준. 사용자 피드백이 오면 버전·변경 이유를 기록합니다. 이전 포스터·Pen 시안보다 이 문서를 우선 적용합니다. 이는 디자인 결정이며 실제 구현 완료 주장이 아닙니다.

## 1. 제품 개념

**결제 전에 판매글과 공식 안내를 차분하게 대조하는 도구.** 분위기는 가볍고 명료하되 근거를 숨기지 않습니다. Linear Mobile의 행 중심 구조와 Flighty의 요약 위계를 참고하되 타사 외형을 복제하지 않습니다. 상세 URL·이미지·공식 코드 문서는 REFERENCE_GUIDE.md의 REF/CODE ID로 인용합니다.

‘안전 판정’, ‘암표 확정’, 신뢰 점수, 가짜 탐지 확률, 실시간 감시 화면을 만들지 않습니다. 큰 레이더 스캔으로 실제 외부 매물을 수집하는 것처럼 보이게 하지 않습니다.

## 2. 반드시 지킬 규칙

- D01: 색·간격·반경·모션은 tokens.json 기준. 화면별 임의 파랑·노랑·그라데이션 금지. 토큰 추가는 근거를 기록.
- D02: 밝은 중립 배경 + 잉크 네이비 본문 + 민트 포인트. 규정 불일치·확인 필요는 앰버, 입력·통신·실행 오류만 붉은색. 녹색은 동작/선택 표시이며 티켓 안전 보증 아님.
- D03: 화면당 지배적인 채움 CTA 하나. 부차 행동은 중립 버튼/텍스트. 작은 터치 영역을 만들지 않는다(공통 최소 48).
- D04: 화면 제목/주요 내용/CTA/모드 표시가 먼저 보입니다. 긴 개발 설명·원시 주소·해시는 ‘연결 및 출처 정보’ 안에. 실제/시연/수동/AI 구분 자체는 항상 보이게.
- D05: `method=model, reused=true, actualModelCall=false`는 ‘이전 AI 추출 재사용’으로 표시하고 새 호출이라고 하지 않습니다. `matched`는 비교 성립이지 안전·정가 일치가 아닙니다. 가상 판매글+공식 자료 조합에서 공식 자료를 가상이라고 표시하지 않습니다. fixture는 ‘시연 예시 · AI 호출 없음’, manual은 ‘직접 입력 · AI 호출 없음’. model은 실제 metadata에 근거할 때만 표시.
- D06: 원문·사용자 수정값·공식 문구를 명확히 구분. 금액 숫자·원문·verifiedAt·URL·정책 scope를 뷰에서 만들거나 변경하지 않습니다.
- D07: 가격 비교 조건 미확인이면 숫자와 안전 체크 아이콘 대신 보류 이유/수정 행동. 정보 부족을 0원·정상으로 표현 금지.
- D08: 결과의 핵심 확인 사항과 이유는 펼침 기본. 출처 세부·전체 입력은 접어도 1회 동작으로 열려야 함. 원문 인용을 삭제해서 간결하게 만들지 않음.
- D09: Reduce Motion·큰 글자·스크린리더·웹 키보드를 지원. 색뿐 아니라 상태 명칭 사용. 일반 텍스트 대비 4.5:1, 큰 글자/의미있는 경계 3:1 목표와 실제 측정값 구분.
- D10: 폼 상태와 API 흐름은 유지. 실서버·합성 fixture 두 모드 모두 검증. 디자인 수정 때문에 응답 검증/조건 입력/늦은 응답 무효화를 제거하지 않음.
- D11: 모션은 장식입니다. 폼 마운트·네트워크·오류 복구·화면 진입을 animationend/timeout에 종속시키지 않습니다. 가짜 진행률·성공 카운트업 금지.
- D12: 새 UI 라이브러리·폰트 다운로드·유료 자산 설치 없음. 시스템 한글 폰트와 기존 스택 사용. 기존 native 폴더 직접 재생성 금지.
