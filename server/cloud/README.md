# 공통 서버 시험 구성

공통 서버는 `ticketradar-shared-staging.daoule-6b5.workers.dev`에 HTTPS로 배포되어 있다. 공개 웹의 공통 거래와 D2 시뮬레이터의 새 앱 빌드가 이 주소를 사용한다. 공통 거래는 가상 결제이며, 실제 계정으로 웹·앱 거래 완료까지 확인하는 검증은 남아 있다.

`MigrationControl`은 Cloudflare 계정에서 연결을 허용한 서비스 바인딩을 통해서만 호출한다. 일반 HTTP 경로에는 이전 기능이 없다. 이전은 고정된 `market-v1` 저장소가 비어 있을 때만 가능하며, 같은 원본의 재시도는 허용하고 다른 데이터로 덮어쓰는 요청은 거절한다. 거래 서비스가 이미 초기화된 객체에서는 이전할 수 없다.

실제 이전 전에 다음을 확인해야 한다.

1. 원본 서버의 모든 쓰기 경로를 중지하고 전환 중 다시 시작되지 않도록 한다. 파일 잠금은 새 코드를 사용하는 협력 프로세스에만 적용되므로 구버전 서버나 다른 파일 편집 프로세스도 종료해야 한다. 단순히 포트가 비어 있는지만 확인해서는 안 된다.
2. `withLockedMarketSnapshot`은 이전 작업이 끝날 때까지 쓰기 잠금을 유지하고, 덮어쓰지 않는 별도 백업을 만든 뒤 파일 해시를 전후 비교한다. 개인정보와 비밀번호 해시를 로그에 출력하지 않는다. 비정상 종료로 잠금 파일이 남으면 원인과 실행 중인 프로세스를 확인하기 전 임의로 삭제하지 않는다. 여러 서버 인스턴스는 각각 메모리 상태를 가지므로 이 잠금만으로 동시 운영을 안전하게 만들 수 없다.
3. 로컬 전용 인증 브리지와 `openMarketCutoverSession`을 통해 잠금을 유지하면서 이전한다. 브리지는 공개 HTTP 주소로 배포하지 않으며 임의의 강력한 인증값을 안전하게 전달해야 한다. 전송 결과의 해시·건수와 원본·백업을 비교하고 오류 시 전환하지 않는다.
4. 별도 계정으로 로그인·매물·거래 흐름과 재시작 후 보존을 검증한다. 전환 준비가 끝나거나 검증이 실패해도 잠금은 유지된다. 실제 트래픽 전환과 기존 서버 중단을 확인한 경우에만 `releaseAfterCutover`를, 전환을 중단하고 원본 복구가 안전하다고 확인한 경우에만 `abort`를 호출한다. 두 확인 함수는 호출자가 구현해야 하며, 단순히 `true`를 반환하면 실제 상태가 검증되지 않는다.

2026-11-15 기존 로컬 계정 4개·거래 2건·매물 10건을 공통 저장소로 이전하고 원본과 해시·건수가 일치함을 확인했다. 로컬 원본과 백업은 남겼으며 `.migrated` 표시로 새 서버 코드의 원본 쓰기와 실행을 막았다. 구버전·비협력 프로세스는 이 표시를 무시할 수 있으므로 별도로 통제해야 한다. 복구 시에는 원격 데이터와의 차이를 먼저 확인하고 양쪽에 동시에 쓰지 않도록 한다.

인증 요청 제한은 공통 저장소에 보존하며 저장에 실패하면 요청을 거절한다. 단일 스냅샷 저장 방식의 크기·성능 한계, 다수 사용자에 대한 요청 제한 운영, Gmail OAuth 테스트 토큰의 만료는 추가 검토가 필요하다. `transferLockedMarketFile` 자체는 전송 후 잠금을 해제하므로 실제 전환에는 잠금을 유지하는 `openMarketCutoverSession`을 사용한다.

제보와 담당자 세션의 저장 기능은 로컬 시험했지만, 기존 담당자 계정이 시연용이어서 공개 서버에서는 `REPORTS_ENABLED`를 설정하지 않아 접수·담당자 API를 차단한다. 실제 담당자 권한과 운영 절차를 정비하기 전 활성화하지 않는다. 실제 비밀값은 저장소에 기록하지 않는다. 기존 제보 파일은 자동 이전하지 않으며, 이 제보함은 정부 기관과의 자동 신고 연계나 실제 주최 측 인증이 아니다.

AI 추출은 기본적으로 꺼져 있다. Cloudflare 환경에서 `EXTRACTION_PROVIDER=gemini`와 서버 전용 `GEMINI_API_KEY`를 명시적으로 설정하는 코드를 준비했지만, 실제 키를 설정하거나 공개 서버에 배포하지 않았다. 모의 제공자 시험은 실제 모델 호출·품질 검증이 아니다. 외부 제공자에 판매글이 전달되는 점과 키의 사용량·유출 여부를 확인한 뒤 적용해야 한다.
